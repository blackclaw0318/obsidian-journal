# 上坤个人网站 · 交互作品集改版

## 目标

保留文章、小说、视频、资源和管理后台的信息结构。首页从内容列表改为个人介绍、可交互的 3D 形象、按时间排列的项目经历和内容入口。每个项目提供独立详情页，说明背景、本人工作与交付成果。

## 视觉与交互参考

用户指定视频：[Vibe Coding 能把简历玩出什么花样？？](https://www.bilibili.com/video/BV1X9gy6gEbP/)。

已观察到的设计：大幅虚拟人物作为背景主体，简历经历叠在人物周围，角色近景与文字形成前后层次；形象和表情使简历从静态文档变成可探索的个人展示。视频中还展示了从人物形象制作 3D 模型的过程。借鉴这些呈现原则，不依赖演示中的付费建模平台。

2026-11-05 按用户新流程重做的实现方向：

- 用户提供的辫发、浓眉、棕色眼睛、耳饰和灰色 Polo 虚拟形象，转换为可渲染、可转动的三维网格。
- 先生成清晰的干净头部底稿与吐舌、惊讶、大笑三张表情设计；只参考两张 Pinterest 图的脸部异形贴纸风格，不借用其中人物。
- 使用 Blender 将头部、眼睛、手、苹果、整片与缺口面包、手机、闪光灯和六枚贴纸拆成独立三维部件；保存可编辑源文件与脚本。
- CODER、MUSICIAN、VIDEO CREATOR、CHRISTIAN、DREAMER、WORK 六枚贴纸作为首页入口；镜头在已验证的正面约 ±30° 范围转向并聚焦所选标签，再进入原有栏目或工作经历。
- 左右眼独立跟随指针；苹果抛接、面包咬下实际缺口、手机闪光、眨眼与表情均通过模型部件驱动；手机也提供同等按钮操作。
- 纸白、炭黑、酸绿和珊瑚红构成整体视觉，文章、小说、视频、资源、工作详情与简历沿用同一套排版和贴纸语言。
- 工作经历归并为四个项目，首页显示重点，阶段和细节留在详情；旧链接保留。
- 三维资源延迟加载、限制像素比与帧率、视口外停止绘制、完整释放纹理和几何体。移动端与减少动画偏好有相应处理；无 WebGL 时显示最终模型的备用图，全部内容入口仍可用。

贴纸风格参考：[第一张](https://www.pinterest.com/pin/705517097930166575/)、[第二张](https://www.pinterest.com/pin/704954147968857609/)。实际生成提示保存在 `scripts/avatar-v4/generation-prompts.json`；建模与导出说明保存在同目录 README。

## 经历数据

通过 sitech-posts skill 在用户授权的 EIP 会话中枚举本人帖子，按最早到最新获取正文，验证作者，记录分页结束条件和失败项。原文、认证、内部地址和证据映射仅保存在仓库之外的私有研究目录。

公开数据只保留适合简历展示的项目主题、时间、工作职责、技术方向与交付物。不发布客户身份、内部系统地址、同事信息、凭据、保密指标或公司原文。不编造职位、任职起止、学历、收入和业务收益。时间范围仅表示材料中可证实的项目活动时间。

旧 README、package.json 版本号与部分历史状态文档滞后，接手基线以 main 提交 3971357 和当前运行服务为准。

## 实现阶段

1. 建立独立开发分支并记录方案；核查视频、采集与运行环境。
2. 整理有来源的经历数据与公开项目介绍。
3. 制作三维角色，完成首页、时间线、详情和全站视觉。
4. 验证类型、构建、数据与关键交互，在桌面和移动端检查实际页面。
5. 分阶段推送 GitHub，备份现有运行版本，在现有服务器发布并检查旧栏目与同机服务。

## 发布约束

开发与构建使用独立目录，不在正在运行的 .next 中构建。保留当前数据库、上传、私有配置和其他服务。以 systemd 的最终生效配置为准，不直接运行历史 deploy.sh（该脚本的端口和进程管理方式已过时）。切换前记录可回滚版本；只重启个人网站服务。
